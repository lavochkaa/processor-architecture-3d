# Ранний замер R3F-бюджета

Замер выполнен до детализации новой сцены командой `npm run build` в существующем Astro-проекте. Временный маршрут `/budget-probe/` лениво загружал R3F `Canvas` с одним `mesh`, `boxGeometry`, `meshBasicMaterial` и `frameloop="demand"`; после измерения маршрут и компонент удалены. Версии: Astro 7.3.8, React 19.3.0, React Three Fiber 9.8.1, Three.js 0.186.1.

| Маршрут | Начальный JS, gzip | Отложенный JS, gzip |
| --- | ---: | ---: |
| Действующий `/scenario/` | 75.6 KiB | 238.6 KiB |
| Минимальный `/budget-probe/` | 69.3 KiB | 233.0 KiB |
| Локальный черновик `/compute/` | 72.6 KiB | 239.4 KiB |

Общий R3F/Three-чанк минимального пробника занимает 232.8 KiB gzip. Из целевого лимита 275 KiB на отложенный 3D остаётся около 42 KiB для кода сцены и добавочных модулей. Измеренный дополнительный вес `/compute/` относительно текущего `/scenario/` с учётом общих чанков — 5.8 KiB gzip. CSS — 5.2 KiB gzip. Это размеры передачи, не замер кадровой частоты: отзывчивость будет проверена отдельно на телефоне или при замедлении CPU.

Скрипт `scripts/check-budget.mjs` теперь анализирует реальные статические и динамические импорты каждого маршрута. Детализацию продолжаем на R3F, но повторяем замер после каждого 3D-подэтапа. При перерасходе сначала сокращаем импорты Three.js и деление чанков, затем оцениваем чистый Three.js без R3F. Повышение лимита потребует отдельного решения.
