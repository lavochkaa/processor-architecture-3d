# План реализации: узнаваемый компьютер и непрерывный путь данных

Основа — [утверждённая спецификация](../specs/2026-10-11-computer-data-path-redesign.md), коммит `03b5541`. Работа ведётся в существующем `/compute/`, без публикации сайта до отдельного подтверждения. Сохранить существующий `/scenario/` и чистую арифметику. Два незакоммиченных файла `src/domain/arithmetic/arithmetic.ts` и `arithmetic.test.ts` принадлежат прежнему черновику: не добавлять и не удалять их без отдельного разбора.

## 0. Базовая линия и контрольные кадры

- Проверить статус Git, текущие тесты, сборку и бюджет gzip. Для поиска кода сначала обратиться к codebase-memory-mcp; если новые узлы отсутствуют в графе, читать известные файлы напрямую.
- Сохранить кадры текущих шагов 2, 4, 8 и 9, а также вид до запуска, чтобы сравнивать не только размер сборки, но и непрерывность маршрута.
- Зафиксировать в отчёте ограничение исходной сцены: `SignalActors` монтируется заново по номеру шага, а 3D скрыто до запуска. Убедиться, что тесты исходной версии зелёные, прежде чем переписывать трассу.

## 1. Десятишаговая семантическая трасса

Файлы: `src/domain/arithmetic/buildTrace.ts`, его тесты, `controller.ts`, словарь `src/content/arithmetic/copy.ts` и тесты словаря/контроллера.

1. Сначала обновить тесты на 10 состояний: ввод, запись A/B в RAM, чтение в CPU-регистры, четыре разряда ALU, сборка результата, запись в RAM, вывод. Пройти все 256 пар. Значения в исходных узлах остаются после копирования; ячейка назначения заполняется только по завершении логического перехода.
2. Расширить тип состояния отдельными ячейками RAM для двух операндов и пятибитного результата. `computeAddition` не менять. Заменить сигналы с безымянными кругами на декларативные пакеты `A`, `B`, `Σ`, плюс перенос с именем `cᵢ`. Трасса задаёт смысл и адреса, но не хранит координаты и длительности.
3. Обновить главы, диапазоны, счётчик, подписи и плоский маршрут. Проверить инварианты прямого/обратного прохода, перехода к главе и `screenValue === a+b` на шаге 10.
4. Запустить `npm test`, `npm run typecheck`, `npm run lint`. Коммит только для трассы, контроллера, текста и тестов. Пока 3D может показывать плоский fallback, но не ложный старый маршрут.

## 2. Общий ввод до запуска и доступный каркас сцены

Файлы: `ComputeApp.tsx`, компоненты панели, `Arithmetic3D.tsx`, новый компонент цифрового блока и тесты компонентов.

1. Вынести A/B, выбор активного поля, ввод цифры, `⌫` и валидацию в единый обработчик. Поля остаются основным способом ввода. Щелчок по 3D-клавише вызывает тот же обработчик; события физической клавиатуры отражаются нажатием клавиши в сцене, не меняя введённое значение дважды.
2. Показывать плату до старта, а не только после `state !== null`. Клавиатура до старта имеет десять читаемых объёмных клавиш, `⌫` и `A/B`; активный операнд указан и в панели, и на блоке. Сохранить проверку `0…15`, фокус на ошибочном поле и `aria-describedby`.
3. Для недоступного WebGL или потери контекста оставить рабочие DOM-поля и плоскую схему. Компонентными тестами проверить синхронизацию 3D-ввода с полем, исправление ошибки, выбранный операнд и сохранность ввода при fallback.
4. Сохранить скриншоты до запуска на desktop и 360 CSS px, отдельный коммит.

## 3. Узнаваемые устройства на одной плате

Файлы: `BoardWorld.tsx`, `sceneLayout.ts`, `cameraPresets.ts`, `TextLabel.tsx` и тесты разметки сцены.

1. Статичный общий план: отдельные RAM-планка, корпус CPU в сокете, SSD, цифровой блок и экран. Для CPU и RAM — видимые корпуса, контактные группы и подписанные порты; SSD подписан «не участвует». Не добавлять GLB и `drei`; повторяющиеся клавиши/контакты создавать инстансингом там, где не нужна отдельная интерактивность.
2. Крупный план CPU: условное раскрытие крышки, внутри регистры A/B, четыре сумматора и пятибитный регистр результата. Сохранить ориентацию битов справа налево и читаемость таблицы. Добавить постоянную подпись границы модели на плате.
3. Сверить макроплан и крупный план с тремя кадрами `docs/reference/`; сделать новые скриншоты шагов 3, 4, 8 и 9 на desktop/телефоне. Проверить, что аппаратные узлы различимы даже без свечения активного шага.
4. Запустить сборку и `npm run test:budget` до анимации. Если бюджет нарушен, убрать декоративную детализацию прежде чем сокращать смысловые компоненты. Отдельный коммит.

## 4. Непрерывные переходы и окна над узлами

Файлы: `SignalActors.tsx`, `signalPaths.ts`, `CameraRig.tsx`, новый координатор переходов и DOM-окно действия.

1. Ввести именованные якоря и маршруты с промежуточными точками для `ввод→RAM`, `RAM→CPU`, `регистры→ALU`, `ALU→результат`, `CPU→RAM`, `RAM→вывод`. Тесты проверяют существование всех адресов трассы, старт точно в источнике и финиш точно в приёмнике.
2. Заменить монтирование актёров по `key={step}` постоянным слоем пакетов. Следующий/предыдущий шаг интерполирует фазу `0…1`; объект отделяется от ячейки источника, проходит весь маршрут и разрешается в ячейке назначения. Никакого появления нового пакета в середине канала. Для `c=0` нет летящего ромба; для `c=1` ромб подписан индексом и на шаге 8 превращается в ячейку бита.
3. Камера, раскрытие CPU, таблица и окно используют ту же фазу. Один DOM-callout проецируется над активным узлом при каждом кадре движения, ограничивается viewport и не закрывает важные ячейки. Прямой переход к главе — явная перемотка: плавная камера и мягкая смена состояния без выдуманной передачи данных через промежуточные шаги.
4. Сохранить кадры начала/середины/конца шагов 2, 3, 4, 8, 9, 10 и короткую запись перехода вперёд/назад. На паузе и после завершения — ноль постоянных кадров рендера. Проверить reduced motion и WebGL loss. Отдельный коммит.

## 5. Интеграция и контроль качества

- Playwright: 10 шагов, `11+6=17`, `0+0`, `15+15`, ввод через DOM и 3D, назад, главы, авто/пауза/скорости, чтение окна, `aria-live`, reduced motion, fallback с отключённым WebGL и `WEBGL_lose_context.loseContext()`.
- Проверить реальные переходы при 1× и 2×: никакой пакет не возникает вне своего источника и не исчезает до появления значения в приёмнике. Сопоставить 3D, RAM, панель, таблицу и плоскую схему в начале и конце каждого шага.
- Замер desktop и смартфона от 360 CSS px, ограничение DPR, отзывчивость на слабом GPU или CPU throttling. Сравнить gzip с прежней сборкой и бюджетами начального JS, 3D и CSS; если появился перерасход, записать причину и оптимизацию.
- `npm run lint`, `npm run typecheck`, `npm test`, `npm run test:e2e`, `npm run test:a11y`, `npm run build`, `npm run test:budget`. Сверить объяснения RAM/CPU/SSD с первичными источниками и сохранить формулировку «один учебный путь».
- Показать локальное превью `/compute/`, ключевые кадры и результаты проверок пользователю. Публичную версию обновлять только после явного «публикуем»; до деплоя зафиксировать предыдущую версию и способ отката.
